# career-app｜受講生アプリ（6週間プログラム）

「オンラインの教室」をコンセプトにした受講生アプリです。機能を部屋に分けています：
エントランス（ホーム）／📚資料室／🤖AI質問室／📅予約室／🗂その他の部屋（課題提出室・応募トラッカー室・掲示板・マイページ）＋🧑‍🏫職員室（admin）。

- 要件：[docs/student-app-requirements.md](../docs/student-app-requirements.md)
- 詳細設計：[docs/student-app-detailed-design.md](../docs/student-app-detailed-design.md)
- 共通ルール：[CLAUDE.md](./CLAUDE.md)

LP（リポジトリ直下）と同じSupabaseプロジェクトを共有します。
このフォルダは自己完結しているため、別リポジトリへ切り出す場合はフォルダごと移動できます。

本番環境：Vercelプロジェクト「training-program」（https://training-program-two.vercel.app）。
このブランチへのプッシュで自動デプロイされます。

## セットアップ

```bash
cd career-app
npm install
cp .env.local.example .env.local   # 値を設定
npm run dev                        # http://localhost:3001（LPと同時起動できるよう3001番）
```

Supabase側の準備：

1. SQL Editor で `supabase/migrations/0001_career_app_schema.sql` を実行（全テーブル・RLS・関数）
2. 続けて `supabase/migrations/0002_storage.sql` を実行（materials / submissions バケットとポリシー）
3. Authentication → URL Configuration で Site URL と Redirect URL に
   `http://localhost:3001/auth/callback`（本番はデプロイ先のURL）を追加
4. **最初の管理者（講師）を作成**：
   - Authentication → Users → Add user → Create new user でメールアドレスを登録（パスワードは任意）
   - SQL Editor で profiles に admin 行を作成：
     ```sql
     insert into public.profiles (id, name, email, role)
     select id, '講師名', email, 'admin' from auth.users where email = '講師のメールアドレス';
     ```
5. 以後の受講生は、アプリの職員室（/admin/students）から登録します（招待制）

## 動作確認手順

### フェーズ1：認証・基盤

1. 未ログインで http://localhost:3001 を開くと `/login` へリダイレクトされること
2. **登録していないメールアドレス**でログインリンクを要求するとエラーになること（招待制）
3. 管理者のメールアドレスでリンクを受け取り、リンクからログインできること
4. 下部タブ（ホーム／資料室／AI質問／予約／その他。adminは＋職員室）が表示されること
5. 職員室 → 受講生 で受講生を登録できること（転職／スキル、期）。登録した受講生のメールでもマジックリンクログインできること
6. 受講生アカウントで `/admin` を開くとホームへ戻されること
7. マイページからログアウトできること

### フェーズ2：資料室

1. 職員室 → 教材 で週を作成（公開日を未来にする）→ 資料室でロック表示（公開予定日つき）になること
2. 公開日を過去に変更すると、週が開けるようになること
3. 動画（YouTube限定公開URL）を登録すると、週の棚に埋め込みプレーヤーで表示されること
4. スライドPDF／テンプレをアップロードし、受講生側の「開く」で署名付きURLが発行されて開けること。
   URLをコピーして1時間後に開くと期限切れになること（直リンク不可）
5. track指定した週（例：career）がスキルトラックの受講生に表示されないこと

### フェーズ3：予約室

1. 職員室 → 面談枠 で枠を作成（定員1）すると、受講生の予約室に表示されること
2. 受講生Aが予約 → 受講生Bには「満席」と表示され予約できないこと
3. 開始24時間前を過ぎた予約はキャンセルボタンが出ないこと（出ていてもサーバー側で拒否）
4. ホームに「次の予約」が表示されること。職員室の「今後の予約がない受講生」に未予約者が並ぶこと

### フェーズ4：課題提出室

1. 職員室 → 課題 で課題を作成（週・締切・対象トラック）
2. 受講生が本文＋ファイルで提出 → 提出済み表示になること。再提出で内容が上書きされること
3. 提出マトリクスのセルが「未（赤系）→ 提出（ティール）→ 済（ネイビー・コメント後）」と変わること
4. セルから提出内容を開き講師コメントを保存 → 受講生の課題詳細にコメントが表示されること
5. 添付ファイルは本人とadmin以外は開けないこと

### フェーズ5：AI質問室

1. `.env.local` に `ANTHROPIC_API_KEY` を設定して受講生で質問 → チューターの回答が返ること
2. 回答スタイル：課題の「答え」を書かずヒントに留める／選考の個別判断は面談へ誘導すること
3. スキルトラックの受講生の質問に、転職・応募の話題が出ないこと
4. 残り質問数が減っていき、上限（既定20問/日）で送信できなくなること（翌日回復）
5. 職員室 → AIログ で全受講生の質問スレッドが閲覧できること

### フェーズ6：応募トラッカー・掲示板・出欠

1. 転職トラックの受講生に「応募トラッカー室」が表示され、スキルトラックには一切表示されないこと
   （URL直打ちでもメニューへ戻される）
2. 応募を記録しステータス・メモを更新できること
3. 職員室 → 応募 で「応募0件」「1週間更新なし」の受講生が強調されること
4. 職員室 → お知らせ で全体／トラック別／期別に配信 → 対象の受講生にのみ表示され、
   ホームに未読バッジ、掲示板を開くと既読になること
5. 職員室 → 出欠 で週×受講生の出欠を記録でき、無断欠席2回以上の行が強調されること
6. 職員室ダッシュボードに「未コメント提出／要フォロー応募／無断欠席／未予約」の件数が出ること
