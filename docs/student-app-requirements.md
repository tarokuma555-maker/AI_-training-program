# 受講生アプリ 要件設計書（教室・部屋ベース構成）

対象リポジトリ：`career-app`（本リポジトリ `career-lp` とは別。Supabaseプロジェクトは共有）
ステータス：**要件確定（2026-08-29 確認事項4件に回答済み。実装着手可）**
前提：CLAUDE.md の背景・表記ルール・デザイントーンに従う

---

## 1. コンセプト：「オンラインの教室」

アプリ全体を1つの校舎に見立て、機能を「部屋」として分ける。
受講生は毎回「どの機能を使うか」ではなく「どの部屋に入るか」で迷わず移動できる。

```
┌─────────────────────────────────────────┐
│  エントランス（ホーム）                        │
│  今週やること・未読お知らせ・次の予約が集まる      │
├──────────┬──────────┬───────────────────┤
│ 📚 資料室   │ 🤖 AI質問室 │ 📅 予約室            │
│ 動画・講義資料 │ チャットボット │ 講義・面談の予約       │
├──────────┴──────────┴───────────────────┤
│ 🗂 その他の部屋                              │
│  ├ 課題提出室                               │
│  ├ 応募トラッカー室（転職トラックのみ表示）        │
│  ├ 掲示板（お知らせ）                         │
│  └ マイページ                               │
├─────────────────────────────────────────┤
│ 🧑‍🏫 職員室（admin専用）                      │
│  提出マトリクス・出欠・応募ダッシュボード・         │
│  スロット管理・お知らせ配信・AI質問ログ           │
└─────────────────────────────────────────┘
```

ナビゲーション（モバイルファースト・下部タブ）：
**ホーム／資料室／AI質問／予約／その他**（adminはさらに「職員室」タブ）

---

## 2. ユーザー種別と認証（プロンプト②から継承）

- `student`：受講生。`track`（career=転職／skill=スキル）と `cohort`（期："2026-1" 形式）を持つ
- `admin`：講師。全データ閲覧・編集可
- 招待制：adminがメールアドレスを登録 → 受講生はマジックリンクでログイン
- RLS：受講生は自分のデータと自分のtrack/cohort向けコンテンツのみ。adminは全件

---

## 3. 各部屋の要件

### 3.1 エントランス（ホーム）

「今週」に必要なものだけを1画面に集約する。

- 今週のゴール・講義日・課題締切（該当週のデータから自動表示）
- 未読お知らせ（バッジ付き）
- 次の予約（予約室のデータから。未予約なら「予約してください」導線）
- 課題の締切前リマインダー表示（アプリ内バッジ。プッシュ通知はしない）
- 修了要件の進捗（出席状況／転職トラックは応募社数）※nice-to-have

### 3.2 📚 資料室（動画・講義資料）

**「週」と「教材の種類」の2軸で、迷わず探せる書庫**にする。

- 構成：週別の棚（第1週〜第6週）×種類フィルタ（🎬動画／📄スライドPDF／🧰配布テンプレ）
- 各週の棚に「この週のゴール」を1行表示（カリキュラムと一体化）
- 自分のtrackに応じた教材のみ表示（common／career／skill）
- 未公開週はロック表示（公開日で自動解放）
- ファイル系教材（PDF・テンプレ）はSupabase Storageに置き、**署名付きURLで配布（直リンク不可）**
- 動画は**YouTube限定公開のリンク方式**（確定）。materials の `external_url` に限定公開URLを保存し、
  資料室内に埋め込み表示。Storageへの動画格納は行わない（帯域コスト回避）
- 教材ごとの補足メモ（講師コメント）欄
- nice-to-have：視聴・閲覧ログ（どの教材が見られていないかを職員室で確認）

### 3.3 🤖 AI質問室（チャットボット）※新規

受講生がいつでもAIに質問できる部屋。**人へのチャット機能とは別物**
（人への連絡は引き続きLINE等。これは実装しない方針を維持）。

- 質問できる範囲：講義内容の復習、Copilotの操作方法、課題の考え方のヒント
- 答えない範囲（講師へ誘導するガードレールをシステムプロンプトに実装）：
  - 個別の選考結果・企業とのやり取りの判断 → 週次面談・講師へ
  - 課題の「答え」そのもの → ヒントまでにとどめる
- 実装：サーバー側でAnthropic APIを呼ぶ（APIキーはサーバー保持。クライアントに出さない）
- システムプロンプトは講座の背景＋表記ルールを含めてコード内定数で管理
- 会話履歴はDBに保存。受講生は自分の履歴を再閲覧できる
- **職員室で質問ログを閲覧可**（よくある質問を講義改善・FAQ化に使う）
- 口調は**丁寧なチューター**（確定）：敬語ベースで用語をかみ砕き、受講生を認めながら導く
- コスト管理：1人あたり**1日20問**を上限（確定・値は設定で変更可能にする）。上限到達時は翌日案内
- 第1期はRAGなし。教材要点をシステムプロンプトに持たせる簡易構成から始め、
  将来的に教材検索（RAG）へ拡張できるテーブル設計にしておく

### 3.4 📅 予約室（個別面談の予約）※新規

- **週1回の講義は固定日時・予約不要**（確定）。講義は出欠記録のみで扱う
- 予約室は**個別面談（週次面談）専用**として実装する
- adminが予約枠（スロット）を作成：日時／定員1／対象track・cohort
  （種別列は将来の講義予約制への拡張用に持たせるが、第1期は meeting のみ使用）
- 受講生はスロット一覧から予約・キャンセル（キャンセル期限：開始24時間前を既定）
- ホームに「次の予約」を表示。未予約の受講生を職員室で確認できる
- 予約変更の通知はアプリ内表示のみ（メール・プッシュ通知はしない）
- Googleカレンダー連携は第1期スコープ外（手動運用）

### 3.5 🗂 その他の部屋

#### a. 課題提出室（プロンプト②フェーズ3を継承）
- 週に紐づく課題（タイトル・説明・締切・対象track）
- 提出：テキスト＋ファイル添付任意。提出済み表示・締切前バッジ
- adminからの返信コメント（1提出につきコメント1つ）

#### b. 応募トラッカー室（転職トラック専用。プロンプト②フェーズ4を継承)
- 企業名・応募日・経路・ステータス（応募済み／書類通過／面接調整中／面接済み／内定／見送り）・メモ
- カード形式で一覧・ステータス更新
- **スキルトラックの受講生にはこの部屋自体を表示しない**（ナビにも出さない）

#### c. 掲示板（お知らせ。プロンプト②フェーズ5を継承）
- 配信対象：全体／track別／期別
- 未読管理（ホームにバッジ）

#### d. マイページ
- 氏名・track・期の確認、ログアウト
- 自分の出席状況・提出状況のサマリ

### 3.6 🧑‍🏫 職員室（admin専用）

- 提出マトリクス：週×受講生で未提出が一目でわかる色分け
- 出欠記録：週×受講生（出席／録画補講／欠席）。無断欠席2回を自動強調
- 応募ダッシュボード：「応募0件」「1週間更新なし」の受講生を強調（週次面談の準備画面）
- スロット管理：予約枠の作成・予約状況・未予約者一覧
- お知らせ配信、受講生（profiles）管理、AI質問ログ閲覧

## 4. DBスキーマ案（要件レベル）

```
profiles          id / name / role(student|admin) / track(career|skill) / cohort
weeks             週番号 / タイトル / 週のゴール / 公開日 / 対象track(common|career|skill)
materials         week_id / 種別(video|slide|template) / タイトル / storage_path or external_url / 講師メモ / 並び順
assignments       week_id / タイトル / 説明 / 締切 / 対象track
submissions       assignment_id / student_id / 本文 / 添付storage_path / 提出日時 / admin_comment
lesson_slots      日時 / 種別(lecture|meeting) / 定員 / 対象track / 対象cohort / メモ
bookings          slot_id / student_id / 状態(booked|cancelled) / 予約日時
ai_chat_threads   student_id / 開始日時 / タイトル(先頭質問から自動)
ai_chat_messages  thread_id / role(user|assistant) / 本文 / 日時
job_applications  student_id / 企業名 / 応募日 / 経路 / ステータス / メモ / 更新日時
announcements     本文 / 配信対象(全体|track|cohort) / 掲載日
announcement_reads announcement_id / student_id / 既読日時
attendance        week_id / student_id / 状態(出席|録画補講|欠席)
```

**重要な設計上の注意：**
LP側（本リポジトリ）が同じSupabaseプロジェクトに `applications`（プログラム申込）テーブルを
既に持っているため、プロンプト②で「applications」とされていた受講生の応募管理テーブルは
**`job_applications` に改名**する（名前衝突の回避）。
申込データ（LP側）→受講生データ（profiles）への「昇格」は、admin承認時に
申込レコードのメールアドレスで招待を発行する運用でつなぐ。

## 5. 実装しないもの（プロンプト②を継承・明確化）

- 決済機能（スキルトラックの受講料は手動運用。アプリに課金導線を作らない）
- **人と人のチャット機能**（連絡は既存のLINE等。AI質問室は人へのチャットではなくAIへの質問専用）
- プッシュ通知・メール通知（第1期は不要。通知はアプリ内バッジのみ）
- Googleカレンダー連携（第1期は手動）

## 7. 決定事項（2026-08-29 確定）

実装前の確認事項4件は、以下のとおり決定済み。

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | 動画の置き場所 | **YouTube限定公開のリンク方式**。Storageは資料PDF・テンプレ用 |
| 2 | 講義の予約 | **講義は固定日時（予約不要・出欠のみ）**。予約室は個別面談専用 |
| 3 | AI質問室の性格 | **丁寧なチューター**（敬語・かみ砕き・受講生を認めて導く）。上限は1日20問（設定で変更可） |
| 4 | その他の部屋の範囲 | **第1期に4つすべて実装**。課題提出室・応募トラッカー室はフル機能、掲示板・マイページは簡易版 |
