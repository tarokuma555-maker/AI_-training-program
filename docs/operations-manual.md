# プログラム運用マニュアル（講師向け）

本番稼働中のシステム一式の運用手引きです。2026-08-30時点。

## 1. 本番環境の構成

| システム | URL | 用途 |
| --- | --- | --- |
| 申込LP | https://career-lp-nine.vercel.app | 集客・申込受付。`/admin` が審査管理（メール＋パスワードでログイン） |
| 受講生アプリ | https://training-program-two.vercel.app | 受講生の教室。`/admin` が職員室（マジックリンクでログイン） |

- **データはすべてSupabase**（プロジェクト：AI_-training-program）。申込・受講生・教材情報・課題・予約・AI会話ログ・応募記録
- **ファイル**（教材PDF・課題添付）はSupabase Storage、**動画**はYouTube限定公開
- **コード**はGitHub `tarokuma555-maker/AI_-training-program`（ブランチ `claude/career-lp-application-system-npq80o`）。
  プッシュすると両システムがVercelで自動デプロイされる
- 環境変数の変更（Vercelダッシュボード）は**次のデプロイから**反映される（変更後に Redeploy が必要）

## 2. 開講前チェックリスト（残タスク）

- [ ] LPフッターの運営者情報・お問い合わせ先の正式表記（文面をClaudeに渡せば反映）
- [ ] プライバシーポリシーの正式文面（現在は雛形）
- [ ] `ANTHROPIC_API_KEY` の設定（console.anthropic.com で発行 → Vercelの両プロジェクト＋ローカルの`.env.local`）
      ※未設定でも申込は保存される（AI一次判定が「未処理」になるだけ）。AI質問室は必須
- [ ] 独自SMTPの設定（下記6章。**受講生を招待する前に必須**）
- [ ] 第1期のcohort表記（例：2026-1）と講義の固定曜日・時刻の確定
- [ ] 通しテスト：LPから申込 → `/admin`で審査 → 職員室で受講生登録 → 受講生ログイン

## 3. 申込から受講開始までの流れ

1. 応募者がLPの申込フォームから送信 → AI一次判定が自動実行（`ai_reviewed`）
2. **LPの `/admin`** で内容とAI判定理由を確認し、最終判断：
   - 承認 → 「無料相談案内メール」の定型文をコピーして送信 → 無料相談を実施
   - 見送り → 「見送り（次期案内）メール」／スキル希望 → 「スキル講座案内メール」
3. 受講が決まったら、**受講生アプリの職員室 → 受講生** で氏名・メール・トラック・期を登録
4. アプリのURLとログイン方法（メールアドレスでリンクを受け取る）をLINE等で案内

## 4. 週次の運用フロー

**週の準備（講義前）**
- 職員室 → 教材：週の公開日を確認（公開日が来ると自動で受講生に開放）。録画・スライド・テンプレを登録
- 職員室 → 課題：今週の課題を作成（締切・対象トラック）
- 職員室 → 面談枠：翌週の個別面談枠を作成

**週次面談の前**
- 職員室ダッシュボードで要対応を確認（未コメント提出／応募0件・1週間更新なし／無断欠席／未予約）
- 応募ダッシュボードで各受講生の応募状況を確認（面談の材料）
- AIログをざっと見て、つまずきの傾向を把握（FAQ化・講義改善）

**講義後**
- 職員室 → 出欠：出席／録画補講／欠席を記録（無断欠席2回で自動強調）
- 提出マトリクス：提出物にコメントを返す（未＝赤、提出＝ティール、コメント済＝ネイビー）

**随時**
- お知らせ配信（全体／トラック別／期別）。受講生ホームに未読バッジが出る

## 5. 各画面のログイン情報

| 画面 | ログイン方法 |
| --- | --- |
| LP `/admin`（審査） | 講師のメールアドレス＋パスワード（Supabaseで設定したもの） |
| アプリ（受講生・職員室共通） | メールアドレスにログインリンクを送る方式。講師も受講生も同じ入口 |

※講師のアカウントは両方共通（同じSupabaseユーザー）。

## 6. メール送信の増強（独自SMTP・受講生招待の前に）

Supabase標準のメール送信は**1時間あたり数通**の制限があり、実運用には不足します。
[Resend](https://resend.com)（無料枠あり）などでSMTPを設定してください：

1. Resendでアカウント作成 → API Key を発行（SMTP用）
2. 送信ドメインを登録・認証（独自ドメインがない場合はResendの共有ドメインでも開始可）
3. Supabase → Authentication → **Emails** → SMTP Settings を有効化し、Resendの
   Host / Port / User / Password（API Key）/ 送信元アドレスを入力
4. テスト：アプリのログインリンクが安定して届くことを確認

## 7. よくあるトラブル

| 症状 | 対処 |
| --- | --- |
| ログインリンクが届かない | 迷惑メール確認 → 標準メールのレート制限の可能性（時間を空ける／6章のSMTP設定） |
| リンクを開くと「無効なリンク」 | リンクは1回限り・短時間で失効。ログイン画面から再送 |
| 「受講生情報が見つかりません」 | 職員室での受講生登録が未了（Authユーザーだけ存在しprofilesがない状態） |
| AI質問室が「回答の生成に失敗」 | `ANTHROPIC_API_KEY` 未設定または無効。Vercelの環境変数を確認して再デプロイ |
| 画面が真っ赤なエラー | Vercelのデプロイ失敗の可能性。Claudeにエラー文を貼って相談 |

## 8. 変更・修正の反映方法

- **文言・機能の変更**：Claudeのこのセッション（または新しいセッション）で依頼 → 修正をプッシュ → 自動デプロイ
- **環境変数の変更**：Vercelダッシュボードで変更 → 対象プロジェクトを Redeploy
- **DBの変更**：`career-app/supabase/migrations/` にSQLを追加してSQL Editorで実行（既存の `setup_all.sql` は冪等なので再実行可）
